# Этап 7: вооружение противников, тактика и выстрелы

Последующие исправления сближения ИИ, манёвров у границ и увеличение поля до 32×24 описаны в **`docs/STAGE_7_NAVIGATION.md`**. Описание поля 20×16 в предыдущих отчётах относится к прежней версии.

Обновлено 2026-11-02. Продолжение доработки боевого прототипа, без перехода к этапу 8.

## Что изменилось

- У боевого NPC при новой игре выбирается один из непустых наборов: только башня, только бортовое оружие или все три орудия. Для текущего тестового врага наборы равновероятны. Оружие сохраняется у NPC и не перебрасывается при подлёте, движении, переходах между системами или загрузке.
- Во встрече перед боем показаны имя и описание корабля, корпус, щит, движение и фактически установленное оружие: название, диапазон урона, дальность, ОД и сектор. Сюжетное описание остаётся заглушкой `TODO описание корабля.`.
- В тестовой встрече с пиратом второй вариант заменён откупом за 200 кредитов. Он доступен при достаточном балансе, списывает деньги и закрывает встречу без боя. Флаг `pirate_test_bribed` предотвращает повтор этой тестовой встречи; корабль продолжает патруль.
- Противник пользуется теми же конусом движения, инерцией, ограничением курса и занятых клеток, что игрок. Отдельного поворота на месте нет.
- ИИ рассматривает достижимые позиции и направления, в том числе несколько последовательных манёвров за ход. Сначала предпочитает позицию, из которой может стрелять самое мощное орудие. Если она недостижима, выбирает более слабое доступное. Бортовому оружию ищет позицию с целью на фланге.
- Мощность для приоритета — средний базовый урон с учётом вероятности и множителя крита. При равном приоритете учитываются ожидаемый урон доступной очереди, точность, свободное пространство впереди и затраты движения.
- После занятия выбранной позиции враг стреляет подходящими орудиями от самого мощного к более слабым. Он не стреляет оружием вне дальности или сектора. Наличие всех трёх орудий не гарантирует залп из всех трёх: цель должна находиться в секторе каждого.
- **Каждое орудие обеих сторон стреляет не больше одного раза за свой ход**, включая промахи. Использованные орудия игрока помечаются и блокируются в интерфейсе. Загрузка не возвращает им выстрел.
- **Все орудия стоят 2 ОД**, при 6 ОД за ход. Двигатель игрока даёт **6 движения вместо 4**, скорость врага — **5 вместо 3**. Штраф от груза и рывок пилота продолжают работать.
- Добавлен тестовый 3D-визуал: растущий луч, одно взрывное облако при попадании, два последовательных при крите. При промахе луч проходит сбоку от цели и взрыва нет. Лучи игрока бирюзовые, противника оранжевые.
- Вся очередь противника показывается по одному выстрелу после завершения его движения. Следующее боевое действие и переход с экрана результата доступны после окончания визуала. Сохранение и загрузка доступны во время анимации.
- Загрузка прерывает незавершённый визуал и показывает уже сохранённое состояние. Она не повторяет урон, выстрелы или взрывы. Старые очереди после загрузки не проигрываются заново.

## Тестовое вооружение

| id | Орудие | Урон | Дальность | Сектор | ОД |
|---|---|---|---:|---|---:|
| `cannon_s` | Башенное — Лазган МК1 | laser 4–7 | 4 | 300°, кроме кормы | 2 |
| `course_cannon` | Курсовое — Автопушка МК1 | kinetic 8–12 | 8 | Линия носа | 2 |
| `broadside_plasma` | Бортовое — Плазмоган МК3 | laser 6–9 | 6 | По 90° на оба борта | 2 |

Урон, точность и крит берутся из JSON оружия. Модификаторы корпуса, настроения безопасницы и уклонения сохранены. У противника бонус экипажа нейтральный; повреждения его корпуса снижают его точность.

## Согласованные поля

В записи врага `data/combat/enemies.json`:

```json
{
  "description": "TODO описание корабля.",
  "loadouts": [
    ["cannon_s"],
    ["broadside_plasma"],
    ["cannon_s", "course_cannon", "broadside_plasma"]
  ]
}
```

Существующий `weapons` теперь содержит пул из трёх описанных орудий. Каждый id из `loadouts` должен присутствовать в этом пуле и иметь запись модуля оружия.

В `flight.npcs[id]` добавлен `weapons`: массив id выбранных орудий. У мирного NPC он пустой. Боевой NPC обязан иметь один из заданных непустых наборов. При запуске боя список копируется в `combat.opponent.weapons` и должен совпадать с сохранённым набором исходного NPC.

В `combat` добавлены:

```json
{
  "fired": { "player": [], "opponent": [] },
  "shots": []
}
```

`fired` содержит id орудий, потративших выстрел в своём текущем/последнем ходе. Список противника сбрасывается перед его ходом, игрока — при начале следующего хода игрока.

`shots` содержит очередь последнего действия стрельбы: один выстрел игрока или очередь противника. Запись:

```json
{
  "shooter": "opponent",
  "weapon": "course_cannon",
  "origin": [8, 8],
  "target": [7, 8],
  "result": "hit",
  "damage": 5.0
}
```

`result`: `miss`, `hit`, `critical`. `damage` — фактически снятые щит и корпус вместе. Существующий `last_shot` остаётся сводкой последнего выстрела без поля `origin`.

DataLoader проверяет непустые наборы, уникальность и существование id, описание врага и одинаковую стоимость всех орудий. GameState проверяет сохранённый комплект, использованные орудия, принадлежность оружия, структуру очереди, отсутствие повторных выстрелов и соответствие её последней записи `last_shot`.

## Как проверить руками

1. F5 → офис → вылет → `TODO pirate name` → «Подлететь». Прочитать установленное вооружение, его урон и дальность. В новой игре набор может отличаться.
2. Сохранить встречу, загрузить её: комплект должен остаться тем же. «Откупиться — 200 кр.» должно списать 200 и закрыть встречу; при нехватке денег вариант недоступен.
3. В новой игре выбрать бой. В начале хода должно быть 6 движения у игрока. Выбрать орудие и клетку: выстрел стоит 2 ОД, повторить его этим орудием в том же ходу нельзя даже после промаха или загрузки.
4. Завершить ход. Следить, как враг занимает позицию для своих секторов и показывает выстрелы по очереди. Бортовой комплект должен разворачиваться манёвром, а не стрелять через нос.
5. Проверить лучи, взрыв при попадании, двойной взрыв при крите и проходящий мимо луч при промахе. После завершения хода игрока его орудия снова доступны.
6. Проверить сохранение во время луча и загрузку: анимация должна прекратиться, урон и использованное орудие сохраниться. Победа, лут и возвращение в полёт по-прежнему работают.

Автоматические проверки: F6 в `tests/stage_seven_enemies.tscn` — 138 проверок; аргумент `--capture-enemies` добавляет ещё 6 снимков. Основная сцена проверок боя `tests/stage_seven.tscn` — 137 проверок; проба настоящего `user://save.json` добавляет 3 при отсутствии существующего файла.

## Ограничения

- В данных остаётся один тестовый тип врага и один враждебный NPC; разные комплектации работают через общий механизм. Описание и диалог — заглушки.
- ИИ выбирает позицию на ход и затем использует подходящие орудия из неё; он не обязан находить сектор для каждого установленного орудия в одном ходе.
- Визуал временный, без звука, частиц и готового арта. Боевые последствия применяются до проигрывания очереди; сохранение фиксирует результат, а не промежуточный кадр.
- Сейвы предыдущей версии без новых полей вооружения, `fired` и `shots` несовместимы. Для проверки нужна новая игра; миграция не добавлялась.
- Обычные пользовательские сохранения не затрагивались: проверки использовали изолированный профиль `.godot/verification-user-data`. Веб-экспорт отдельно не запускался; потоков и внешних процессов в коде игры нет.
- Коммит не создавался.
