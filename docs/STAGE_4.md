# Этап 4: заказы и репутация

## Что сделано

- Хаб закреплён как отдельное здание: карточка мостика убрана из его навигации, прямые переходы в корабельные помещения удалены.
- В здании добавлен кабинет `hub_office` с действием `orders`, открывающим ПК.
- В JSON заданы шесть шаблонов: по два `private`, `state`, `crime`.
- Требования к репутации, доступ к терминалу и вместимость трюма определяют возможность приёма заказа.
- Активные заказы резервируют массу груза. При успехе или провале место освобождается.
- Награды, штрафы, репутация и реакции экипажа применяются через `EffectApplier`.
- Репутации `state`, `mafia`, `private` ограничены диапазоном от -100 до 100.
- При выполнении `action_tags` влияют на отношение героинь на борту с учётом их собственных `tag_weights` и множителя настроения.
- Просрочка автоматически применяет `failure` один раз. Для криминальных заказов включается флаг `mafia_hunt`.
- Повторные нажатия, повторная загрузка и уже закрытые заказы не дублируют награды или штрафы.

## Согласованное расширение сейва

В `GameState` и `user://save.json` добавлены поля:

```json
{
  "reputation": { "state": 0, "mafia": 0, "private": 0 },
  "orders": {
    "ord_private_01": { "status": "active", "accepted_day": 1 }
  }
}
```

Допустимые статусы: `active`, `completed`, `failed`. Срок вычисляется как `accepted_day + deadline_days`; отдельного поля срока в сейве нет.

Выполнение разрешено до конца дня срока включительно. Например, заказ с `deadline_days: 2`, взятый в день 1, можно выполнить в день 3. Просрочка срабатывает утром дня 4.

## Как проверить руками

1. Нажать F5. В верхней навигации здания должны быть зал, коридор, мастерская, душевые и кабинет. Мостика среди них нет.
2. Перейти в `TODO office`, затем нажать `orders` внизу слева.
3. В терминале отображаются шесть заказов. Нижние карточки доступны через прокрутку.
4. Найти `ord_private_01`, нажать `+`. Статус станет `active`, в трюме будет зарезервировано 2 единицы массы.
5. Нажать `✓` в его строке. Это тестовое завершение доставки: деньги изменятся с 1000 до 1600, `private` — с 0 до 1. Откроется `ord_private_02`.
6. Проверить `×` в строке активного заказа: это провал с последствиями из `failure`. `×` в верхнем углу закрывает только окно и сохраняет активные заказы.
7. Для просрочки перезапустить F5, снова взять `ord_private_01` и нажать `wait` 12 раз. На утро дня 4 заказ станет `failed`, деньги — 880, репутация `private` — -1. Повторное ожидание не повторяет штраф.
8. Для автоматических проверок открыть `tests/stage_four.tscn` и нажать F6. Ожидается `Stage 4 checks: 121 passed, 0 failed`.

`+` — принять; `✓` — тестовая доставка; `×` в строке — провал. Неактивные кнопки означают, что условия, статус или вместимость не позволяют действие. В доработке к этапу 5 карточки получили оплату, систему и планету назначения. Подсказка карточки показывает описание заказа, подсказки кнопок — названия действий; JSON больше не выводится.

## Ограничения прототипа

- `✓` завершает тестовый заказ без полёта. Проверка прибытия в систему назначения появится вместе с картой и полётом.
- На этапе 4 системы были только справочником для ссылок `from`/`to`. Карта и маршруты добавлены на этапе 5; см. `docs/STAGE_5.md`.
- Масса заказов вычисляется по активным заказам; инвентарь предметов относится к отдельному этапу.
- Каждый из шести тестовых заказов можно взять один раз за новую игру. Генерации повторных экземпляров пока нет.
- Фон кабинета и портреты остаются заглушками. Тексты заказов — `TODO`.
- Сейвы без новых полей `reputation` и `orders` отклоняются; миграция не реализована.
